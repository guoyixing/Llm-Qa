问题说明

请求结束时的取消状态没有传入后台重试上下文，已排队的尝试仍会继续执行。

影响

调用方取消后，后台工作仍可能占用执行槽位并写入已过期的合成结果；连续重试会放大无效资源消耗。

建议

由 scheduleRetry 显式接收取消令牌，在每次尝试和结果写入前检查状态，并让取消路径进入可识别的终态。

问题说明

批次中的每条记录都会重新读取相同的只读配置，调用次数随记录数量线性增加。

影响

在大批次下，重复读取会增加锁竞争与处理延迟；复杂度由一次配置读取变为与记录数相同的读取次数。

建议

在进入循环前加载一次不可变配置快照并传给 mapRecord；配置失效逻辑继续由提供者统一处理。

规则或代码证据

合成规则 PERF-DEMO-003。RecordBatchLoader.loadBatch 在记录循环内调用 settingsProvider.load，参数固定为 sample.policy，且循环体不会改变该配置。
