# 公共性能规范

本文件关注会随请求量、数据量或并发量放大的性能风险。规则 ID 以 `PERF` 开头，必须保持唯一和稳定。性能结论应基于调用位置、数据规模和可观察证据，不能仅凭个人偏好判定违规。

## 可复制的规则模板

```markdown
### PERF-<三位序号> <规则标题>

- ID：PERF-<三位序号>
- 级别：<REQUIRED 或 ADVISORY>
- 适用范围：<具体范围>
- 规则：<具体要求>
- 例外：<明确条件或“无”>
- 检查重点：<核对证据>
- 建议：<修改方向>
- 来源：<可定位来源>
```

### PERF-001 避免在循环内执行数据库调用

- ID：PERF-001
- 级别：REQUIRED
- 适用范围：随输入集合大小增长的循环、映射、递归和逐项处理
- 规则：不得在循环内逐项执行数据库查询或写入，导致调用次数随元素数量线性增长；应采用批量查询、批量写入、连接查询或预取。
- 例外：项目规则可以为有严格数据上限、非请求热路径且有明确来源的场景建立覆盖，必须引用 `PERF-001` 并写明上限和恢复条件。
- 检查重点：数据库调用是否位于循环体或间接调用链中，迭代次数是否受外部数据控制，事务是否被重复创建。
- 建议：收集键后一次查询并建立映射，使用批量接口，或把操作下推到数据库执行。
- 来源：公共规范 `standards/common/performance.md`

### PERF-002 避免在循环内执行网络或文件调用

- ID：PERF-002
- 级别：REQUIRED
- 适用范围：随输入集合大小增长的循环、映射、递归和逐项处理
- 规则：不得在循环内无界地逐项发起网络请求或文件读写；必须采用批量接口、受控并发、流式处理或合并读写，并设置资源上限。
- 例外：协议不支持批量且项目规则明确规定最大项数、超时和并发上限时，可以按覆盖范围执行。
- 检查重点：间接网络调用、文件重复打开关闭、请求数量、并发上限、超时和失败重试放大。
- 建议：批量获取或写入，复用安全连接，使用有界工作队列，并汇总部分失败。
- 来源：公共规范 `standards/common/performance.md`

### PERF-003 消除 N+1 数据访问

- ID：PERF-003
- 级别：REQUIRED
- 适用范围：列表查询后按每条记录继续加载关联数据的路径
- 规则：列表处理不得为每条主记录单独加载相同类型的关联数据，形成一次主查询加多次关联查询的 N+1 模式。
- 例外：数据源只能逐项访问时，必须由项目规则定义严格上限、缓存策略和来源。
- 检查重点：属性访问或序列化是否触发延迟加载，关联查询次数是否随列表长度增长，缓存是否真正跨迭代复用。
- 建议：使用预加载、连接查询、批量键查询或数据加载器，并验证查询次数不随结果条数增长。
- 来源：公共规范 `standards/common/performance.md`

### PERF-004 避免循环内重复计算不变量

- ID：PERF-004
- 级别：REQUIRED
- 适用范围：循环、递归、批处理和高频调用路径
- 规则：与迭代项无关且结果稳定的解析、编译、排序、转换或聚合不得在每次迭代中重复执行。
- 例外：计算结果依赖循环中变化的隐式状态，或提取后会破坏正确性时可以保留，但必须能说明依赖。
- 检查重点：表达式依赖项、对象构造、正则编译、配置解析、集合排序和重复序列化。
- 建议：把不变量移到循环外，按稳定键缓存，或预先计算可复用结构。
- 来源：公共规范 `standards/common/performance.md`

### PERF-005 数据读取和缓存必须有界

- ID：PERF-005
- 级别：REQUIRED
- 适用范围：数据库查询、文件读取、网络响应、队列拉取、缓存和内存集合
- 规则：来自外部或持续增长来源的数据必须设置分页、大小、条数、时间窗口或淘汰上限，不得无界读取或永久累积。
- 例外：由类型和业务契约共同保证为固定小集合的数据可以一次读取，但边界必须可定位。
- 检查重点：全表查询、一次读取完整文件、无限队列、无淘汰缓存、分页上限和压缩后膨胀。
- 建议：采用分页或流式处理，设置硬上限和拒绝策略，并监控截断或淘汰结果。
- 来源：公共规范 `standards/common/performance.md`

### PERF-006 避免不必要的串行化等待

- ID：PERF-006
- 级别：REQUIRED
- 适用范围：彼此独立的数据库、网络、文件和后台任务调用
- 规则：独立且可安全并发的高延迟操作不得因逐项等待而完全串行化；并发执行时必须设置上限，并保留错误聚合与取消语义。
- 例外：操作存在顺序依赖、共享限额、事务约束或下游明确要求串行时应保持串行。
- 检查重点：调用间数据依赖、逐项等待、并发上限、下游容量、结果顺序和部分失败。
- 建议：使用有界并发或批量接口，先证明独立性，再保留结果对应关系和失败摘要。
- 来源：公共规范 `standards/common/performance.md`

### PERF-007 缩小锁范围并控制竞争

- ID：PERF-007
- 级别：REQUIRED
- 适用范围：高频或并发路径中的锁、事务锁和同步临界区
- 规则：持锁范围必须限制在共享状态的必要操作内，不得在锁内执行高延迟外部调用、无界循环或与共享状态无关的计算。
- 例外：正确性要求原子覆盖外部操作时，必须有可定位设计来源，并设置超时和容量保护。
- 检查重点：锁等待时间、临界区大小、锁内输入输出、全局锁、读写比例和热点键。
- 建议：锁外准备数据，分片共享状态，使用更细粒度同步，并在不破坏正确性的前提下降低竞争。
- 来源：公共规范 `standards/common/performance.md`

### PERF-008 控制分配、复制和内存驻留

- ID：PERF-008
- 级别：REQUIRED
- 适用范围：大集合、大对象、高频路径、流处理和缓存
- 规则：不得无必要地复制完整大对象、重复构建大型中间集合或让已处理数据长期驻留；内存使用必须随配置上限或处理窗口受控。
- 例外：为保证不可变性、安全隔离或原子快照所需的复制可以保留，但应说明数据上限。
- 检查重点：完整切片或数组复制、链式中间集合、字符串重复拼接、缓存键值保留、流转内存和对象生命周期。
- 建议：使用流式或分块处理，复用安全缓冲区，减少中间表示，并为缓存设置容量和淘汰策略。
- 来源：公共规范 `standards/common/performance.md`
