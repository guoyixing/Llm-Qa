# 公共可读性规范

本文件关注代码能否被准确理解和维护。规则 ID 以 `READ` 开头，必须保持唯一和稳定。没有规则 ID 的个人写法偏好只能标为 `ADVISORY`。

## 可复制的规则模板

```markdown
### READ-<三位序号> <规则标题>

- ID：READ-<三位序号>
- 级别：<REQUIRED 或 ADVISORY>
- 适用范围：<具体范围>
- 规则：<具体要求>
- 例外：<明确条件或“无”>
- 检查重点：<核对证据>
- 建议：<修改方向>
- 来源：<可定位来源>
```

### READ-001 名称与行为一致

- ID：READ-001
- 级别：REQUIRED
- 适用范围：函数、变量、类型、参数和返回值
- 规则：名称必须准确说明内容或行为，执行写操作、远程调用或状态变化的函数不得使用暗示纯读取的名称。
- 例外：无。
- 检查重点：名称是否反映副作用、单位、集合与单值、同步与异步，以及成功与失败语义。
- 建议：按真实职责重命名，必要时拆开查询与修改操作。
- 来源：公共规范 `standards/common/readability.md`

### READ-002 单元保持明确职责

- ID：READ-002
- 级别：REQUIRED
- 适用范围：函数、方法、类型和模块
- 规则：每个代码单元必须有可概括的主要职责，不得同时承担彼此独立的校验、持久化、格式化和外部通知流程。
- 例外：仅编排多个步骤的入口可以连接不同职责，但不得内嵌各步骤的复杂实现。
- 检查重点：是否存在多个变化原因、无关依赖、难以命名的代码块或必须整体阅读才能理解的局部逻辑。
- 建议：提取有业务含义的单元，并让编排层只表达执行顺序和结果传递。
- 来源：公共规范 `standards/common/readability.md`

### READ-003 控制流直接表达主路径

- ID：READ-003
- 级别：REQUIRED
- 适用范围：条件、循环、分支和提前返回
- 规则：控制流必须让主路径、失败路径和终止条件清晰可见，不得使用无必要的深层嵌套、隐式跳转或难以验证的复合条件。
- 例外：语言或框架强制的结构可以保留，但应在允许范围内降低嵌套。
- 检查重点：分支是否互斥且完整、提前返回是否改变清理行为、循环出口是否明显、条件名称是否可理解。
- 建议：先处理无效输入和失败路径，为复杂条件命名，并拆分互不相关的分支。
- 来源：公共规范 `standards/common/readability.md`

### READ-004 魔法值必须说明业务含义

- ID：READ-004
- 级别：REQUIRED
- 适用范围：影响业务判断、容量、时间、重试、协议或资源限制的字面值
- 规则：具有业务或运行含义的数字和字符串必须命名或配置，并说明单位与来源，不得在多个位置散落重复字面值。
- 例外：零、一、空集合等在局部表达中含义直接且不承载业务策略的值可以原样使用。
- 检查重点：值的含义、单位、边界、重复次数，以及变更时是否需要同步修改多处。
- 建议：提取为具名常量或配置项，并在名称或说明中标明单位和决策来源。
- 来源：公共规范 `standards/common/readability.md`

### READ-005 注释解释原因而非复述代码

- ID：READ-005
- 级别：REQUIRED
- 适用范围：实现注释、接口说明和临时兼容说明
- 规则：注释应解释无法从代码直接得知的原因、约束、权衡或外部契约，不得只把代码动作换成自然语言重复一遍。
- 例外：教学示例或生成文档所需的逐步说明不属于本规则范围。
- 检查重点：删除注释后是否丢失关键背景，注释是否解释了决策原因，是否存在可用清晰命名替代的注释。
- 建议：先改善名称和结构，再补充决策背景、限制条件和可定位来源。
- 来源：公共规范 `standards/common/readability.md`

### READ-006 注释必须与当前实现一致

- ID：READ-006
- 级别：REQUIRED
- 适用范围：代码注释、待办说明、示例和文档字符串
- 规则：修改代码时必须同步更新或删除已经过期、与行为冲突或会误导审查者的注释。
- 例外：记录历史行为的变更文档可以保留，但必须明确标为历史信息，不能伪装成当前约束。
- 检查重点：参数、返回值、边界、错误行为和待办条件是否仍与实现相符。
- 建议：删除无维护价值的注释，把长期约束放到稳定文档，并为临时说明附上可验证的移除条件。
- 来源：公共规范 `standards/common/readability.md`
