# 公共稳健性规范

本文件定义输入、状态、资源和并发失败下的基本要求。规则 ID 以 `ROBUST` 开头，必须保持唯一和稳定。未配置的容错偏好只能作为 `ADVISORY` 建议。

## 可复制的规则模板

```markdown
### ROBUST-<三位序号> <规则标题>

- ID：ROBUST-<三位序号>
- 级别：<REQUIRED 或 ADVISORY>
- 适用范围：<具体范围>
- 规则：<具体要求>
- 例外：<明确条件或“无”>
- 检查重点：<核对证据>
- 建议：<修改方向>
- 来源：<可定位来源>
```

### ROBUST-001 明确处理空值和缺失值

- ID：ROBUST-001
- 级别：REQUIRED
- 适用范围：外部输入、配置、查询结果、可选字段和集合访问
- 规则：代码必须区分缺失、空值、空字符串和空集合的业务含义，并在首次可信边界完成处理，不得依赖偶然的空值异常。
- 例外：类型系统已经证明值不为空且来源可信时，不要求重复检查。
- 检查重点：空值传播、默认值是否掩盖错误、可选链后的结果、集合首项访问和反序列化缺失字段。
- 建议：在边界解析为明确类型，为合法缺失值建立显式分支，对非法缺失值返回可识别错误。
- 来源：公共规范 `standards/common/robustness.md`

### ROBUST-002 校验边界值和极端输入

- ID：ROBUST-002
- 级别：REQUIRED
- 适用范围：索引、区间、长度、数量、时间、金额、分页和数值运算
- 规则：实现必须覆盖最小值、最大值、空输入、单元素、越界、溢出和精度边界，并让区间是否包含端点保持一致。
- 例外：无。
- 检查重点：小于、等于和大于边界时的行为，整数溢出，时间边界，分页偏移，以及单位换算。
- 建议：集中定义边界和单位，在入口拒绝非法值，并使用不会溢出或丢失精度的数据类型。
- 来源：公共规范 `standards/common/robustness.md`

### ROBUST-003 循环必须有可证明的终止条件

- ID：ROBUST-003
- 级别：REQUIRED
- 适用范围：普通循环、轮询、分页遍历、递归和状态机
- 规则：循环或递归必须存在可验证的进度和终止条件；依赖外部状态时必须设置时间、次数或数据上限，不得无限等待。
- 例外：设计为常驻的事件循环可以不自然终止，但必须支持受控取消、资源释放和失败恢复。
- 检查重点：每次迭代是否推进状态、退出条件能否到达、分页游标是否更新、取消信号是否传播。
- 建议：增加明确上限和超时，记录终止原因，并对游标不变或状态停滞快速失败。
- 来源：公共规范 `standards/common/robustness.md`

### ROBUST-004 异常不能被吞掉或伪装成成功

- ID：ROBUST-004
- 级别：REQUIRED
- 适用范围：异常捕获、错误返回、降级和批处理结果
- 规则：失败必须通过异常、错误结果或明确的部分失败状态传递，不能返回与真实状态不符的成功，也不能只记录日志后继续产生误导结果。
- 例外：明确允许跳过单项失败的批处理可以继续，但必须汇总失败项和未完成范围。
- 检查重点：捕获后控制流、默认返回值、成功计数、错误上下文、退出状态和调用方判断。
- 建议：使用可区分的结果类型，保留根因，并让状态、消息和实际副作用一致。
- 来源：公共规范 `standards/common/robustness.md`

### ROBUST-005 资源在所有路径可靠释放

- ID：ROBUST-005
- 级别：REQUIRED
- 适用范围：文件、网络连接、数据库连接、流、锁、临时资源和订阅
- 规则：资源获取后必须在成功、失败、取消和提前返回路径上可靠释放，释放顺序应与依赖关系相符。
- 例外：生命周期由明确框架容器托管的资源可以由容器释放，但所有权必须清楚。
- 检查重点：异常路径、嵌套资源、提前返回、取消回调、重复释放和资源所有权。
- 建议：使用语言提供的作用域管理机制，并把获取和释放放在可审查的相邻边界。
- 来源：公共规范 `standards/common/robustness.md`

### ROBUST-006 重试必须有边界且避免放大故障

- ID：ROBUST-006
- 级别：REQUIRED
- 适用范围：网络、数据库、消息和其他外部调用的自动重试
- 规则：重试必须限定可重试错误、最大次数或截止时间，并采用退避；可能产生副作用的操作必须证明幂等或使用幂等键。
- 例外：无。
- 检查重点：重试错误分类、次数、超时、退避、抖动、幂等性，以及多层重试叠加。
- 建议：只在最合适的一层重试，传播最终错误，并记录尝试次数和最终状态。
- 来源：公共规范 `standards/common/robustness.md`

### ROBUST-007 并发共享状态必须防止竞态

- ID：ROBUST-007
- 级别：REQUIRED
- 适用范围：线程、协程、任务、进程或请求间共享的可变状态
- 规则：共享状态的读取和修改必须具备明确的一致性策略，不得依赖未经保证的执行顺序，也不得用检查后执行的分离步骤制造竞态窗口。
- 例外：不可变数据或由运行时证明为单执行上下文的数据不需要额外同步。
- 检查重点：原子性、可见性、共享容器、缓存刷新、重复提交、取消与完成同时发生的路径。
- 建议：减少共享可变状态，使用原子操作、消息传递或范围清晰的同步机制。
- 来源：公共规范 `standards/common/robustness.md`

### ROBUST-008 锁顺序和等待必须避免死锁

- ID：ROBUST-008
- 级别：REQUIRED
- 适用范围：互斥锁、读写锁、信号量、事务锁和跨资源协调
- 规则：多锁获取必须采用一致顺序，持锁期间不得执行无界等待或不受控外部调用，并应为可失败等待提供超时或取消路径。
- 例外：由框架保证单锁或无阻塞的临界区可以不额外设置超时，但仍需保持最小持锁范围。
- 检查重点：锁获取顺序、嵌套锁、回调重入、持锁调用外部系统、异常时解锁和等待依赖环。
- 建议：缩小临界区，建立统一锁顺序，避免锁内调用未知代码，并记录超时后的恢复策略。
- 来源：公共规范 `standards/common/robustness.md`

### ROBUST-009 部分失败必须保留可恢复状态

- ID：ROBUST-009
- 级别：REQUIRED
- 适用范围：批处理、跨服务操作、多步骤写入和并行任务聚合
- 规则：发生部分失败时必须区分已完成、未执行、失败和状态未知的部分，不得把整体标为成功，也不得盲目重复已经生效的副作用。
- 例外：具备已验证原子事务的操作可以整体回滚并返回单一失败结果。
- 检查重点：提交边界、补偿操作、幂等性、任务汇总、重放行为，以及状态未知时的处理。
- 建议：记录每个步骤的稳定标识和结果，提供安全重试或补偿路径，并向调用方返回完整摘要。
- 来源：公共规范 `standards/common/robustness.md`
